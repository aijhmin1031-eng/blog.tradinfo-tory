# 도토리경제 특집 편성 기준 v1.0

특집(주제 허브)은 링크 모음이 아니라 **그 자체로 읽히는 기획 지면**이다.
처음 온 독자가 이 페이지 하나로 주제의 현재 국면을 따라잡을 수 있어야 한다.
2026-08-22 제정. 에디토리얼·데이터 제작·성과(SEO) 3개 관점의 설계 심사를 거쳐 종합했다.

## 1. 방침 — 특집이란 무엇이어야 하는가

1. **한 페이지 완결성** — 개별 기사를 읽지 않아도 "지금 어디까지 왔는가"가 파악되는 살아있는 대시보드 + 쌓이는 아카이브.
2. **고정 서사 구조** — 모든 특집은 같은 문법을 따른다:
   ① 왜 지금 이 주제인가(리드) → ② 지금 수치(타일·차트) → ③ 맥락(연표) → ④ 해설(기사) → ⑤ 언어(용어) → ⑥ 다음 확인 지점.
3. **수치는 파이프라인만** — 특집 페이지의 모든 수치는 `data/series/*.json`·`corp.json` 등 자동 산출물에서 빌드 시 렌더한다.
   페이지·리드 문단에 수치 하드코딩 금지. 수동 요소는 낡지 않는 텍스트(리드·큐레이션)로 한정한다.
4. **살아있는 지면** — 데이터는 매일 자동, 편집(리드·연표·확인 지점)은 월 1회 점검. 기준 시점을 지면 상단에 표기한다.
5. **유지 공수 상한** — 특집 1개의 정기 수동 작업은 **월 30분 이내**. 이를 넘게 만드는 요소는 자동화하거나 채택하지 않는다.
   특집 수가 늘어도 일일 수동 작업 증가분은 0이어야 한다.

## 2. 개설 요건 — 어떤 주제가 특집이 될 자격이 있나

| # | 요건 | 기준 |
|---|---|---|
| 1 | 지속 뉴스성 | 향후 6개월 이상 수치 변동·후속 기사가 예상되고, 정기 확인 지점(월간 통계·분기 공시·정책 일정)이 3개 이상 |
| 2 | 데이터 지속성 | 자동 파이프라인(관세청·금융위·ECOS·FRED·DART) 중 **3종 소스에서 시계열 4개 이상**을 기존 수집기 설정 추가만으로 확보 가능 |
| 3 | 기사 재고 | 개설 시 소속 기사 **4편 이상** (입문 성격 1편 필수). 특례: 2편 + 2주 내 2편 계획 확정 시 "개설 중" 표기로 개설 가능 |
| 4 | 정체성 적합 | 검증 가능한 수치로 말할 수 있는 주제일 것 — 의견·전망만으로 채워야 하는 주제는 부적격 |
| 5 | 용어 수요 | 용어 사전 매핑 6개 이상 (신규 등재 포함, 특집 간 중복 매핑 허용) |

일회성 이벤트는 특집이 아니라 기획 기사 1편으로 처리한다.

## 3. 구성 요소 — 최소 기준

| 요소 | 필수 | 기준 |
|---|---|---|
| 갱신 표기 | ✅ | 페이지 상단에 **데이터 기준 시점(자동)**과 **편집 갱신일(수동 점검일)**을 구분 표기 |
| 리드(전문) | ✅ | "왜 지금 이 주제인가"에 답하는 3~5문장. 핵심 수치 1개 이상을 시리즈 값 바인딩으로 인용(하드코딩 금지) |
| 핵심 수치 타일 | ✅ | 6개 이상, 출처 기관 3곳 이상 혼합. 단일 시리즈에서 파생한 타일은 최대 2개. 전 타일 기준 시점 표기 |
| 마크 차트 | ✅ | 3개 이상: ① 대표 지표 추세 ② 구조 단면(품목·국가·이면 지표) ③ 시장 지표(관련주 등). 각 차트에 해설 캡션 2~3문장 + 출처·갱신 주기 |
| 연표(타임라인) | ✅ | 국면 전환 사건 5~8개. 날짜 + 한 줄 + 출처. 지나간 확인 지점을 이곳으로 이월 |
| 해설 기사 목록 | ✅ | 4편 이상, 역할 라벨(입문/데이터/심층) 부여, "처음이라면 이 순서로" 읽기 순서 명시. frontmatter `topics` 태그로 자동 수집 — 슬러그 하드코딩 금지 |
| 용어 박스 | ✅ | 6개 이상(픽토그램 포함), `topics.ts`의 glossaryKeys로 명시 매핑 — 사전 그룹 통째 참조 금지 |
| 다음 확인 지점 | ✅ | 3개 이상. 일정·주기 + "무엇이 어떻게 나오면 어떤 의미인지" 한 줄. 서사의 종결부이므로 생략 불가 |
| 상호 링크 | ✅ | 소속 기사 전편에 특집 배너(기사→특집 역링크). 일방향 링크 금지 |
| 토리의 노트 | 권장 | 현재 국면 요약 4~6문장, 수치와 기사 사이의 다리. 전망 단정 금지 |
| 관련주·공시 박스 | 권장 | 상장기업이 핵심인 주제는 사실상 필수 — corp.json 필터로 전자동 렌더 |
| FAQ | 권장 | 검색 파생 질문 3~5문답 — 검색 스니펫·롱테일 유입용 |

## 4. 개설 절차

1. **개설 점검표** — 요건 5항의 근거(기사 슬러그·시리즈 파일명·확인 지점·용어 후보)를 명시. 1개라도 미달이면 보류.
2. **지면 설계** — 고정 서사 순서로 목차 초안: 어떤 시리즈로 어떤 차트를, 어떤 기사에 어떤 라벨을.
3. **데이터 준비** — 수집기 설정 추가(`data/sources.json`, `trade.mjs`의 ITEMS·COUNTRIES, `corp.mjs`의 WATCHLIST) + 백필 + 원 출처와 3개 지점 수치 대조.
4. **부족 콘텐츠 선발행** — 기준 미달 상태로 독자를 만나지 않는다.
5. **페이지 구현** — 이 문서의 구성 요소 표와 1:1 대조.
6. **등록·배선** — `topics.ts` 등록(내비·인덱스 자동 반영), 소속 기사 배너 확인.
7. **발행 후 검수** — 다음 날 자동 갱신 반영·링크·출처 확인, 첫 편집 갱신일 기록.

## 5. 유지·종료 규칙

- **일일**: 파이프라인 자동 갱신. 특집 추가로 늘어나는 일일 수동 작업은 0.
- **신선도**: 시리즈 `updatedAt`이 갱신 주기의 2배(월간 기준 45일)를 넘으면 해당 타일·차트를 노출하지 않는다 — 낡은 수치를 최신처럼 보이는 것은 무출처 수치와 같은 급의 위반.
- **신규 기사**: frontmatter `topics` 태그 부여만으로 자동 편입. 태그 누락은 발행 미완료로 간주.
- **월 1회(30분)**: 리드 시의성, 지나간 확인 지점의 연표 이월, 새 국면 반영, 편집 갱신일 갱신.
- **분기**: 시리즈 구성(HS코드·감시 종목·상대국) 재검토. 검색 유입·체류 확인.
- **종료**: 6개월간 신규 기사 0편이면 **아카이브** — 내비 드롭다운에서 내리되 URL과 자동 갱신은 유지, 인덱스에 아카이브 표기. 방치 상태(갱신도 종료 표시도 없음)는 허용하지 않는다.
- **총량**: 동시 활성 특집 3~5개. 신규 개설은 기존 특집 전부가 기준 충족 상태일 때만.
