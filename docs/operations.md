# 도토리경제 운영 체계

> 이 문서는 도토리경제의 데이터·콘텐츠 자산이 어디에 어떻게 쌓이고, 매일 무엇이 자동으로
> 일어나는지를 정의한다. 구조 변경 시 이 문서를 함께 갱신한다.

## 1. 자산 구조 — 무엇이 어디에 쌓이나

| 경로 | 내용 | 관리 방식 |
|---|---|---|
| `data/sources.json` | **지표 정의서** — 수집 대상 시계열의 출처·통계코드·주기·단위 | 수동 편집. 지표 추가는 여기에 한 줄 |
| `data/series/*.json` | **장기 축적 시계열** — 매일 수집분이 날짜 기준으로 병합·누적 | 파이프라인 자동. git 이력이 곧 데이터 이력 |
| `src/data/indicators.json` | 티커·지표 타일용 최신 스냅샷 | 파이프라인 자동 생성 |
| `src/content/briefs/*.json` | **데일리 브리핑** — 규칙 기반 자동 생성 문서 | 파이프라인 자동. 날짜당 1건, 멱등 |
| `src/content/posts/*.mdx` | **기사** — 반자동(초안 생성 후 검토·발행) | 사람이 최종 승인 |
| `src/assets/` | **화면에 쓰는 그림 정본**(hero·cat·story·poses·tori·packthumb) | 수동. 빌드가 리사이즈·WebP 처리 |
| `public/images/` | **내려받기 대상만**(그림함 원본·og-default) | 수동. 최적화 안 됨 |
| `docs/worldview.md` | 세계관·편집 원칙 | 수동 |

## 2. 매일 일어나는 일 (자동)

평일 아침 KST 06:50, GitHub Actions가 다음을 수행한다.

1. **수집(collect)** — `sources.json`의 전 시계열을 ECOS·FRED에서 수신,
   `data/series/`에 병합 축적, `indicators.json` 재생성
2. **발행(brief)** — 최신 영업일 종가로 데일리 브리핑 JSON 생성
   (결정론적 규칙 문장 — 추측·전망 문장은 생성하지 않는다)
3. **축적 커밋** — 변경분을 저장소에 커밋 (데이터 이력 보존)
4. **빌드·배포** — 사이트 재빌드 후 GitHub Pages 반영

필요 조건: 저장소 Secrets에 `ECOS_API_KEY`, `FRED_API_KEY`.
수동 실행: Actions 탭 → Deploy to GitHub Pages → Run workflow.

로컬 실행:

```bash
ECOS_API_KEY=... FRED_API_KEY=... npm run pipeline
```

## 3. 기사 발행 절차 (반자동)

1. 초안 작성 — 포맷 고정: **세 줄 요약(무슨 일/왜 중요/다음 체크) → 결론형 제목의 차트 →
   본문 → 토리의 한 마디**
2. **수치 검증** — 기사에 들어가는 모든 숫자는 `data/series/` 축적분 또는 공식 API
   응답에서 나와야 한다. 검증 불가 수치는 싣지 않는다 (세계관 철칙 ①)
3. 검토·승인 후 `src/content/posts/`에 커밋 — 푸시가 곧 발행
4. 발행 후 확인 — 라이트/다크, 모바일 폭, 차트 라벨

## 4. 품질 기준 (발행 전 점검표)

**신규·보강을 가리지 않고, 커밋 전에 게이트를 돌린다.**

```bash
node scripts/check-quality.mjs --linkable   # 쓰기 전: 링크 걸어도 되는 기사 목록
node scripts/check-quality.mjs <슬러그>      # 커밋 전: 통과 필수
```

게이트가 검사하는 것(신규 글도 동일, 물타기 비교만 생략된다):

- [ ] `sources` 배열에 **실제로 확인한 출처**가 있고 URL이 달렸는가
- [ ] 끝맺음이 **「실무에서 틀리기 쉬운 지점」**(설명) 또는 **「다음에 확인할 것」**(데이터)인가
- [ ] **긴 대시(—)를 한 개도 안 썼는가**
- [ ] 내부 링크가 **`--linkable` 목록 안**에 있는가(예약 기사끼리는 발행 순서까지 볼 것)
- [ ] **내부 링크가 0개는 아닌가** ← 2026-08-26에 이 구멍으로 데이터 기사 14편이 샜다
- [ ] 문단이 350자 이하인가

게이트가 못 보는 것(사람이 본다):

- [ ] 모든 수치에 출처와 기준일이 있는가
- [ ] 차트 제목이 결론을 말하는가
- [ ] 상승 빨강 / 하락 파랑 관습을 지켰는가
- [ ] 어절 단위 줄바꿈이 깨지는 곳은 없는가 (모바일 확인)
- [ ] 투자 자문으로 읽힐 표현이 없는가 (철칙 ②)
- [ ] 공포 조장 헤드라인이 아닌가 (철칙 ③)
- [ ] **`<Term t="...">` 용어가 `src/lib/glossary.ts`에 있는가** ← 없으면 그 기사가 발행되는
      날 아침 빌드가 통째로 실패한다(2026-08-25 실제 발생, 9/24 발행분에서 사전 적발)

## 기사 집필 기준 — 검정 문단 (2026-08-25 신설, 소유주 승인)

104편 전수 진단(8/25 일지)에서 확인된 병: **데이터 기사에 서술만 있고 검정이 없다.**
그래서 「수출은 신기록, 주가는 롤러코스터」가 SK하이닉스 급등락을 HBM·수율 탓으로 잘못
지목한 채 발행됐다(실제로는 코스피 베타 1.60 · R² 94.1%). 재발 방지를 위한 규칙.

### 규칙 — 숫자로 인과를 주장하는 모든 기사에 적용

원인을 지목하는 문장을 쓸 때는, **그 주장을 반증하려 시도한 문단을 반드시 함께 싣는다.**
"왜 그런가"를 설명만 하고 넘어가는 기사는 발행하지 않는다.

절차 세 줄:

1. **비교 대상을 고른다.** 지수(코스피·달러인덱스), 동종 업계, 같은 국면의 과거,
   영향받지 않았어야 할 대조군 중 하나 이상.
2. **대 본다.** 우리 `data/series/`에 이미 있는 계열로 계산한다. 상관·회귀·같은 날 등락
   비교 무엇이든 좋다. 새 API를 붙일 필요는 거의 없다.
3. **결과를 그대로 쓴다.** 초고의 설명이 틀렸으면 **틀렸다고 쓰고 고친다.**
   이 과정 자체가 기사의 가장 좋은 대목이 되는 경우가 많다(8/25 기사가 그 예).

### 함께 지킬 것

- **대조군을 반드시 넣는다.** "A가 B 때문"이라 쓰려면 B의 영향을 안 받았어야 할 것도
  같이 보여준다. 8/25 기사의 HMM(베타 0.06)이 그 역할이다.
- **표본 크기와 한계를 밝힌다.** n이 작으면 작다고 쓴다. 숨기면 그 자체가 결함이다.
- **끝맺음은 「오늘의 결론」이 아니라 성격에 맞게.**
  데이터 기사 → **「다음에 확인할 것」**(지표 이름과 판단 기준선을 함께).
  설명 기사 → **「실무에서 틀리기 쉬운 지점」**.
- **자료 각주**: 기사 끝에 `<p class="src-note">`로 출처 링크·조회 구간·한계·면책을 단다.
  스타일은 `PostLayout.astro`에 전역으로 있다.

### 읽기 시간은 손으로 쓰지 않는다

`readingMinutes` 프런트매터 필드는 8/25에 **폐지**됐다(표기 6.5분 / 실제 1.7분이었다).
`lib/site.ts`의 `readingMinutesOf()`가 본문 한글 글자수로 실측한다(500자/분).
프런트매터에 다시 넣지 말 것.

### 출처 표기 (2026-08-25 신설)

- 프런트매터 `sources:` 배열(`org`·`name`·`url`·`note`)에 **실제로 쓴 것만** 적는다.
  기사 끝 「자료」 블록과 구조화 데이터 `citation` 이 여기서 자동 생성된다.
  **비어 있으면 둘 다 생략된다** — 없는 출처를 지어 넣지 않기 위한 설계다.
  (이전에는 104편 전부에 같은 `citation` 문자열이 하드코딩돼 있었다.)
- 표준 출처는 `src/lib/sources.ts`. `SeriesChart` 를 쓰는 기사는 계열 id 로 자동 역산되므로
  대개 손댈 일이 없다. 자체 계산·가공이 들어갔으면 `도토리경제 · 자체 분석`을 **표본 조건과 함께** 추가한다.

### 10년 맥락 (2026-08-25 신설)

- `<SeriesContext series="usdkrw" label="원/달러 환율" />` — 보유 전 구간에서 **백분위·중앙값·최저·최고**를
  계산해 "지금 이 숫자가 역사적으로 어디인가"를 한 줄로 보여준다.
- 서사용 `SeriesChart`(짧은 구간)는 그대로 두고 **그 아래에 얹는다.** 둘은 역할이 다르다.
- 주의: **"가장 높다"는 정말 최고치일 때만** 나온다. 백분위 99%와 최고치는 다르다
  (미 국채 10년 4.74%는 상위 1%지만 10년 최고는 4.98%).

### 끝맺음 (⑤ 진행 상황)

- **데이터 기사 14편 = 완료.** 「오늘의 결론」 → **「다음에 확인할 것」**,
  각 항목에 지표 이름과 **판단 기준선**을 함께 적었다(예: "두 달 연속 감소가 첫 확인선").
- **설명 기사 81편 = 미완.** 「실무에서 틀리기 쉬운 지점」으로 바꾸려면 기사마다 **새 내용을 써야** 한다.
  제목만 갈아 끼우면 내용과 어긋나므로 기계적 치환 금지. 순차 집필 대상.

## 보강 3종 세트 — 기존 설명 기사 86편 (2026-08-25 계획 승인, 실행 대기)

계획서: https://claude.ai/code/artifact/7dd6a179-b54c-43e4-8b29-7159d55c2ef1
실행 목록: `docs/backfill-queue.md` (Tier A 55편 + Tier B 31편, 얇은 것부터 정렬)

### 전제 — 분량은 목표가 아니라 결과다

"2배로 늘리자"를 목표로 삼으면 같은 말을 다시 쓰고 배경 설명을 부풀리게 된다.
**얇은 기사보다 나쁜 것이 부풀린 기사다.** 아래 세 조각을 붙이면 분량은 따라온다.
증거: 8/25 `memory-stocks-summer` 개편이 792자 → 1,334자(1.68배)가 됐는데,
늘리려고 늘린 문장은 하나도 없다. 검정 문단과 기준선이 붙은 결과다.

### 0. 먼저 도입부 재탕을 걷어낸다 (2026-08-25 신설)

**세 조각을 붙이기 전에 이걸 먼저 한다.** 반복을 지워야 어디에 무엇을 채울지 보인다.

우리 조판은 화면 위쪽에서 **요약을 세 번** 한다 — 요점3줄(`three`) · `KeyStat` · 본문 첫 문단.
셋이 같은 숫자를 쓰면 독자는 **같은 문장을 세 번 읽는다.** 8/25 실측에서
`krw-1400-three-signals`는 도입부에서만 4개 수치를 재탕하고 있었다.

역할을 이렇게 가른다.

| 부품 | 맡을 일 |
|---|---|
| 요점3줄(`three`) | 결론. 이것만 읽어도 되게 |
| `KeyStat` | **딱 한 숫자.** 머리기사 격 |
| **본문 첫 문단** | **숫자 재탕 금지.** 장면·질문으로 연다 |
| `PointCards` | **본문 요약 금지.** 본문에 없던 각도를 준다(누구에게 무엇이 달라지나 등) |

`PointCards`가 본문을 되풀이하는 것도 같은 병이다. 8/25 실측 평균 겹침은 2%로 낮지만
`krw-1400`(49%)·`exchange-rate-quotes`(26%)·`letter-of-credit-basics`(26%)·`fx-hedge-basics`(24%)
네 편이 눈에 띈다.

### 기사당 한 번, 세 조각

1. **우리 숫자 한 조각** (+200~300자) — `data/series/`에서 그 주제에 닿는 실측치를 붙인다.
   설명만 하던 글에 **도토리경제만 쓸 수 있는 문단**이 생긴다.
2. **「실무에서 틀리기 쉬운 지점」** (+250~400자) — 「오늘의 결론」을 걷어내고 교체.
   그 주제에서 사람들이 **실제로 틀리는 지점**을 쓴다.
3. **진짜 출처** (+80~150자) — 원문을 **확인해서** `sources` 배열에 넣는다.
   자료 블록과 `citation`이 자동으로 붙는다.

**Tier B는 2·3번만** 적용한다 — 데이터를 억지로 붙이지 않는다.

**기준 분량(2026-08-25 소유주 지시로 확정)**: **1,500자 내외.**
소유주 지시: "기준은 1,500자 내외로 설정할 것. **내용의 품질이 중요하다.**"
- **하한선이 아니라 기준점이다.** 1,400자대여도 새 사실이 충분하면 통과다.
  반대로 1,800자여도 같은 말을 늘린 글은 실패다. 숫자를 맞추려 문장을 붙이지 않는다.
- 참고 실측(8/25): 3종 세트를 제대로 붙이면 대체로 1,400~1,700자에 앉는다.
  그 범위를 벗어나려고 조각을 억지로 늘리는 것이 바로 물타기다.
- 판단 순서는 언제나 **① 새 사실이 들어왔는가 ② 읽기 편한가 ③ 분량**이다.
  분량이 모자라 보이면 «쓸 말을 더 찾아라»는 신호이지 «같은 말을 늘려라»가 아니다.

### 쓰기 전 체크리스트 (2026-08-25 신설 — 게이트에 걸리고 고치는 낭비를 없앤다)

게이트는 **사후 검사**다. 걸린 뒤 고치면 이미 두 번 일한 것이다.
8/25 `krw-1400` 보강에서 끝맺음 누락·긴 대시·죽은 링크로 **세 번 되돌아갔다.**
아래를 **쓰기 전에** 확인하면 한 번에 끝난다.

```bash
node scripts/check-quality.mjs --linkable   # 지금 링크 걸어도 되는 기사 목록
```

| 쓰기 전 확인 | 안 지키면 |
|---|---|
| 새 **출처 1건 이상**을 먼저 확보했나 | 실패(물타기 판정). 분량이 150자 넘게 늘면 출처도 늘어야 한다 |
| 끝맺음 제목이 **「실무에서 틀리기 쉬운 지점」**(설명) 또는 **「다음에 확인할 것」**(데이터)인가 | 실패 |
| 「오늘의 결론」을 지웠나 | 실패 |
| **긴 대시(—)를 한 개도 안 썼나** | 실패. 마침표·쉼표·콜론, 나열은 가운뎃점(·) |
| 내부 링크가 **`--linkable` 목록 안**에 있나 | 실패(독자에게 404) |
| 문단이 **350자 이하**인가 | 경고 |
| 분량이 **1,500자 내외**인가 | 경고(하한선 아님, 품질이 우선) |

**특히 긴 대시와 죽은 링크가 반복 실수다.** 초안을 쓰는 동안 `—`를 아예 타이핑하지 않고,
링크는 위 명령 결과를 열어 둔 채 그 안에서만 고른다.

### 통과 기준 (물타기 게이트)

- **새 사실이 들어왔는가** — 늘어난 분량에 검증된 숫자나 새 출처가 최소 하나 동반돼야 한다.
  글자만 늘고 `sources`가 그대로면 **물타기로 보고 되돌린다.**
- **끝맺음이 바뀌었는가** — 「오늘의 결론」이 남아 있으면 보강 완료로 치지 않는다.
- **출처가 실재하는가** — URL은 실제로 확인한 것만. **그럴듯한 주소를 지어 넣는 것은 무출처보다 나쁘다.**
- **금지** — 같은 말 다시 쓰기 · 형용사 늘리기 · 배경 설명 확장.

### 발견해 둔 소재 (첫 견본용)

**관세청 통계는 수출을 FOB로, 수입을 CIF로 집계한다**(8/25 확인).
수입액에는 운임·보험료가 포함되고 수출액에는 없다. 그래서 우리가 이미 쓴
「반도체 무역수지 243.4억 달러」는 **기준이 다른 두 숫자를 뺀 값**이고, 운임·보험료만큼
흑자가 실제보다 작게 잡힌다. 매일 관세청 API를 받는 쪽만 할 수 있는 이야기이며,
`fob-vs-cif` · `trade-balance-vs-current-account` · `import-duty-calculation` ·
`incoterms-2020-guide` **네 편을 함께 살린다.**

## 구조·문단·연결 원칙 (2026-08-25 소유주 지시 — 모든 기사 공통)

소유주 지시: "읽기 편한 것이 가장 중요하다. 기승전결까지 꼭 맞출 필요는 없고 지금
구조도 괜찮다. 다만 읽기 편한 상태로 세팅하라. 우리 기사가 우리 기사를 언급하면
링크를 걸어 독자가 계속 머물게 하라. 토리 이야기를 끌어오면 그것도 링크하라.
문단·줄바꿈 원칙을 세워 적용하라." 아래는 그 원칙이다. 보강·신규 집필 모두에
적용하고, 매일 아침 Routine도 이 절을 보고 쓴다.

### 1. 흐름 (읽기 편함이 목표 — 기승전결은 강제가 아니라 기본형)

목표는 **읽기 편한 글**이다. 아래 네 마디는 잘 읽히는 글이 대체로 갖는 기본형일 뿐,
틀에 억지로 맞추지 않는다. 주제에 따라 마디를 합치거나 순서를 바꿔도 된다.

- **도입**: 독자가 실제로 부딪히는 장면·질문으로 여는 편이 잘 읽힌다(견적서 한 줄,
  뉴스 헤드라인, "어느 쪽이 싼가?"). 긴 배경 설명으로 열지 않는다.
- **전개**: 개념·구조를 **표·차트·PointCards로** 편다. 벽 같은 줄글 나열은 피한다.
- **이 기사만의 대목**: 데이터 기사는 **검정 문단**(통념을 우리 숫자로 되짚기),
  설명 기사는 **「우리 숫자 한 조각」**. 여기서 글이 "검색하면 나오는 일반론"과 갈린다.
- **끝맺음**: **「실무에서 틀리기 쉬운 지점」**(설명) 또는 **「다음에 확인할 것」**(데이터).
  판단 기준선을 함께. 「오늘의 결론」은 쓰지 않는다.

무엇보다, 소제목으로 이야기의 마디를 끊어 독자가 어디쯤인지 알게 하고, 문단을
짧게 유지하는 것(아래 2번)이 읽기 편함의 핵심이다.

### 2. 문단·줄바꿈 원칙 (읽기 편함)

- **한 문단 = 한 생각.** 새 내용·새 국면이 시작되면 반드시 문단을 바꾼다(**빈 줄** 하나).
  MDX에서 문단 구분은 빈 줄로만 생긴다 — 문단 안의 단순 개행은 렌더에서 합쳐지므로,
  원문 하드랩(줄 길이)은 신경 쓰지 말고 **빈 줄의 위치**만 관리한다.
- **한 문단은 화면 3~5줄을 넘기지 않는다.** 한글 350자를 넘어가면 두 문단으로 쪼갠다
  (게이트가 이 초과를 경고로 잡는다).
- **세 항목 이상 나열·대조는 줄글이 아니라 표·PointCards로.** 벽 같은 문단을 만들지 않는다.
- 어절 단위 줄바꿈(`word-break: keep-all`)은 레이아웃이 처리하니 본문에서 신경 쓰지 않는다.

### 3. 내부 연결 원칙 (체류 시간 — 소유주 핵심 지시)

- **다른 우리 기사의 내용을 언급·인용하면 반드시 링크한다.** 형식은 루트 절대경로:
  `[자연스러운 텍스트](/posts/<슬러그>/)` — base 없이(정본 Vercel base `/` 기준, 저장소 관례).
- **링크 텍스트는 "여기"가 아니라 그 기사의 핵심어**로 단다(맥락이 미리 보이게).
- **특집 소속 기사는 허브로도 한 번**: `/topics/semiconductor-ai/`.
- **토리 이야기(만화)를 끌어오면** `/story/<슬러그>/`로 링크
  (현재 화: `first-acorn` 기원 · `daily-01` · `daily-02` 일상 · `life` 일대기).
- **낯선 용어는 `<Term t="..." />`** — 자동으로 `/glossary/`로 연결된다.
- **보강 기사는 내부 링크를 최소 1개** 목표로 한다(관련 기사가 있을 때. 억지 링크는 금지).
  게이트가 내부 링크 수를 세어 0이면 경고한다.
- 원칙: **링크는 독자에게 다음 읽을거리를 건네는 일**이다. 관련 있으면 아끼지 말되,
  한 문단에 셋 이상 몰지 않는다(읽기가 끊긴다).

### 4. 인용 가능성 3종 (2026-08-26 소유주 지시 — 게이트가 강제한다)

소유주 지시: "우리 기사들은 두괄식에, 글이 목록화 되고 표로 잘 정리가 되어 있어야 한다.
그래야 인용도 쉽고 읽기도 쉽다." 이 절이 그 지시의 규칙판이다.

**왜 읽기 편함과 따로 적는가.** 우리 병목은 품질이 아니라 노출이다(`traffic.md`).
남이 우리를 인용하려면 **들어 올릴 수 있는 한 문장**이 있어야 한다. 그런데
구글 스니펫과 LLM 은 요약 카드(`ThreeLines`)가 아니라 **본문 첫 문단과 소제목**을 집어 간다.
사람에게는 이미 두괄식이었지만 기계에게는 아니었다.

**착수 시점 실측(107편)**: 리드에 수치 36% · 수치형 소제목 7% · 표가 아예 없는 글 33편.

1. **두괄식 리드.** 본문 **첫 문단**에 이 기사의 **결론 수치**를 적는다. 기준시점도 함께
   (`dataAsOf` 프런트매터로 갈음해도 된다). 배경·질문으로 여는 도입은 그 다음 문단으로 민다.
2. **핵심 발견 소제목만 수치형.** 소제목 **하나**에 발견을 숫자로 적는다
   (「홍콩, 일방통행의 중계 항구」 → 「홍콩, 수출 43.7억 대 수입 0.3억」).
   **나머지 소제목은 지금의 문학적 톤을 유지한다**(소유주 결정). 전부 수치형으로 바꾸지 않는다.
3. **표 최소 1개, 단위를 붙여서.** 비교 축이 **둘 이상**일 때만 표로 만든다.
   2행짜리 장식용 표는 만들지 않는다(줄글이 낫다). 숫자가 든 표에는 단위를 붙인다 —
   단위 없는 숫자는 그 표만 떼어 인용할 수 없다. 개념 대조표(FOB 대 CIF)에는 단위가 없는 것이 맞다.

**「글의 목록화」는 전면 적용하지 않는다(소유주 논의 결과).** 이유는 둘이다.
전면 불릿은 **가장 AI스러운 형식**이라 절대 규칙 4와 부딪힌다. 그리고 우리를 남과 가르는 것은
**검정 문단**인데, **불릿은 사실을 담고 줄글은 추론을 담는다.** "이 표의 첫 줄이 이 기사의
설명을 배신한다" 같은 문장은 불릿에 담기지 않는다. 목록화하면 우리 고유의 부가가치가 먼저 죽는다.
그래서 위 2번(문단·줄바꿈 원칙)의 **"세 항목 이상 나열·대조는 표·PointCards로"** 가 상한이다.

**어디서 강제되나**
- `npm run check-quality <슬러그>` — **신규 기사는 실패, 기존 기사는 경고**다.
  기존 107편을 한꺼번에 빨갛게 켜면 빨간불이 상시가 되고, 상시가 된 경고는 안 보게 된다.
- `npm run audit` — 기존분의 **순서**는 여기가 정한다(`리드 비두괄식` 55 · `소제목 무수치` 50 ·
  `표 없음` 45). 전부 90 미만이라 CI 빨간불은 켜지 않는다.
- `PointCards` 는 2026-08-26 부터 `<ul>/<li>/<h3>` 로 조판한다(보이는 모습은 그대로).
  이전 `<div>` 더미는 **기계가 목록으로 읽지 못했다** — 107편이 요점 카드를 갖고도
  인용 대상이 되지 못하던 이유가 여기였다.

**주의 — `audit` 의 「도입부 재탕」 판정을 함께 좁혔다.** 첫 문단이 요약 카드의 수치를
하나 되풀이하는 것은 이제 **규칙이 시키는 일**이라 옛 판정과 정면으로 부딪혔다.
그래서 수치 2개 이상 + 표현까지 겹칠 때만 재탕으로 센다(미결 22번: 위양성은 슬러그 예외가
아니라 판정 규칙을 좁혀서 없앤다).

## 6. 재고 구성 — 미리 쓰는 것과 발행일에 쓰는 것 (2026-08-28 소유주 결정)

**예약 재고는 「하루도 안 거르고 발행」을 보장하는 장치다. 그런데 그 보장을 «미리 쓰는 것»으로
사기 때문에, 무엇을 미리 쓰는지가 최신성을 결정한다.**

2026-08-28 실측에서 재고 41편의 구성이 **뒤집혀 있었다** — trade 17 · money 16 · tariff 7 ·
**basics 1**. 안 낡는 분야가 1편이고, 낡는 분야가 40편이었다. `dataAsOf → pubDate` 지연은
중앙값 19일 · 최대 37일이었다. 그 결과 `base-rate-275` 는 「기준금리 2.75%」라는 제목으로
발행 예정이었는데, 나흘 앞선 8월 27일에 기준금리가 3.00% 가 됐다.
**발행 시점에 이미 틀린 제목이 자동으로 나갈 뻔했다.**

### 규약

| 성격 | 미리 쓰는가 | 예 |
|---|---|---|
| **제도·정의·절차** (에버그린) | **재고로 미리 쓴다** | 까르네 · AEO · 원산지 표시 · 통관 절차 · 관세평가 |
| **구조 해설** (수치는 예시) | 미리 써도 된다 | 명목과 실질 · 물가지수 읽는 법 · 환전 수수료의 구조 |
| **현재 상태를 주장** | **발행일에 가깝게 쓴다** | 기준금리 3.00% · 엔화 876원 · 월 수출 327억 달러 |

- **판별 기준은 카테고리가 아니라 「제목이 현재값을 약속하는가」다.** money·trade 안에도
  에버그린이 많고(포워더와 관세사, 병행수입), basics 에도 시점 수치가 들어갈 수 있다.
- 시점 의존 기사를 굳이 미리 써야 한다면 **`<SeriesChart>` 를 붙인다.** 차트는 매일 갱신되므로
  본문이 스냅숏이어도 독자가 현재값을 함께 본다. 다만 **차트만 갱신되고 문장은 안 갱신된다는
  것**을 잊지 말 것 — 제목에 수치를 박으면 차트와 제목이 서로 어긋난다.
- **제목에 현재 수치를 박는 것은 가장 위험하다.** 본문의 과거 비교 수치(945원에서 876원으로)는
  낡지 않지만, 제목의 수치는 독자에게 하는 약속이라 어긋나면 거짓이 된다.

### 기계가 지킨다

`npm run precheck` 가 **예약 기사 제목의 수치를 우리 시계열의 현재값과 직접 대조**한다
(2026-08-28 신설). 차이가 2~50% 면 경고한다 — 2% 미만은 정상 변동, 50% 이상은 애초에
같은 대상을 가리키는 수치가 아니다.

**이 검사를 만들며 두 번 헛짚었다. 되풀이하지 말 것.**
1. 「제목에 숫자가 있으면 경고」 → 예약분 5건 **전부 오탐**. 면세 한도 800달러·우대율 90%·
   보조금 527억 달러는 정책 상수·예시라 낡지 않는다.
2. 「자료가 21일 이상 묶었으면 경고」 → **실제 사고를 못 잡았다.** `base-rate-275` 의 지연은
   9일뿐이었고 그 9일 사이에 정책이 바뀌었다. **나이는 잘못된 신호다.**
3. 지금 방식(현재값 직접 대조)이 그 사고를 정확히 잡고 오탐은 0건이다.

## 7. 섹션별 서술 형식 (2026-08-28 소유주 결정 — 「다 똑같은 양식이라 식상하다」)

### 왜 바꿨나 — 실측이 지적을 뒷받침했다

발행분 69편 전수:

| 요소 | money | tariff | trade | basics |
|---|---:|---:|---:|---:|
| **PointCards** | **100%** | **100%** | **100%** | **100%** |
| Term | 76% | 100% | 90% | 89% |
| 표 | 94% | 100% | 72% | 70% |
| 소제목 평균 | 5.3 | 5.8 | 4.3 | 4.9 |
| Spark | 0% | 0% | 0% | 0% |

**69편 전부가 PointCards를 쓴다.** 소제목 수도 4.3~5.8 로 사실상 같다. 분야별로 다른 것은
차트 유무뿐이고, 그것은 편집 판단이 아니라 **데이터가 있냐 없냐**로 갈린 것이다.
만들어 놓고 한 번도 안 쓴 컴포넌트(`Spark`)도 있다.

원인은 **절대규칙 8(인용 3종)이 분야를 안 가리고** 걸려 있던 데 있다. 인용 3종은 데이터
기사에 맞는 규칙인데 전 분야에 강제되니, 개념 설명글도 억지로 표를 갖고 억지로 수치형
소제목을 달았다.

### 교환한 것

**소유주가 인용 가능성 일부를 내주고 다양성을 택했다**(2026-08-28: 「받아들이고 진행하자.
이게 맞음.. 다양성 확보」). `상식 사전`에서 표·수치형 소제목을 면제하면 그 분야의 인용
가능성은 내려간다. 그 대신 읽는 맛과 분야의 성격을 얻는다.

**두괄식 리드는 내주지 않았다.** 전 분야 공통으로 남긴다 — 검색엔진·LLM 이 집어 가는
자리라 거기서 물러나면 다양성이 아니라 그냥 인용 불가가 된다.

### 분야별 형식

| 섹션 | 읽는 방식 | 서술 형식 | 두괄식 | 수치형 소제목 | 표 |
|---|---|---|:-:|:-:|:-:|
| **수출입 리포트** trade | 데이터 확인 | **리포트형** — 리드 수치 → 차트 → 표 → 검정 → 다음 확인 | 강제 | **강제** | **강제** |
| **돈의 흐름** money | 메커니즘 이해 | **경로 추적형** — 출발점 → 1차 파급 → 2차 파급 → 시차. 소제목이 경로의 단계 | 강제 | 면제 | 강제 |
| **관세·통상** tariff | 실무 판단 | **분기형** — 조건 → 갈림 → 예외 → 틀리기 쉬운 지점. 표는 **판별표** 역할 | 강제 | 면제 | 강제 |
| **상식 사전** basics | 개념 습득 | **문답형** — 정의 → 왜 필요한가 → 흔한 오해 → 한 문장 요약. 짧게 | 강제 | 면제 | **면제** |

**영문판은 리포트형 하나로 간다**(데이터 데스크이므로, `english-edition.md`).

### 기계가 지킨다

`check-quality.mjs` 와 `audit.mjs` 가 **같은 `FORM` 표**를 들고 분야별로 가른다.
두 파일에 표가 중복돼 있으니 **한쪽만 고치지 말 것.**

적용 뒤 실측(발행·예약 110편):
- 표 없음 — money 7 · trade 13 · tariff 1 · **basics 0**
- 소제목 무수치 — **trade 24 만**
- 리드 비두괄식 — 네 분야 전부(공통 규칙이므로 정상)

### 요약 장치도 분야별로

**PointCards 100% 를 깨는 것**이 이 작업의 핵심인데 규칙만으로는 안 깨진다.
규칙을 갈라도 요약 장치가 하나뿐이면 결국 같은 모양이 된다.

| 형식 | 요약 장치 |
|---|---|
| 리포트형 trade | **표** (비교 축 둘 이상) + `SeriesChart` |
| 경로 추적형 money | 단계형 소제목 자체가 요약 · `KeyStat` 로 출발점 수치 |
| 분기형 tariff | **판별표** (조건 → 해당 여부) |
| 문답형 basics | **`<AskBlock>`** (2026-08-28 신설) |

`AskBlock` 은 `PointCards` 와 셋이 다르다 — 아이콘이 없고, 제목이 **물음표로 끝나는 질문**이고,
**세로 목록**이라 읽는 순서가 강제된다(카드 그리드는 눈이 아무 데나 먼저 간다).
질문은 세리프, 답은 산세리프로 결을 갈라 문답이 한 덩어리로 뭉치지 않게 했다.

```jsx
<AskBlock items={[
  { q: '코픽스가 무엇인가', a: '은행이 자금을 조달한 평균 비용이다.' },
  { q: '왜 내 대출 금리가 이걸 따라가나', a: '변동금리 대출의 기준으로 쓰이기 때문이다.' },
]} />
```

**PointCards 를 금지하지는 않는다.** basics 에서도 나열이 진짜 필요하면 쓸 수 있다.
바꾼 것은 「기본값처럼 매번 쓰는 것」이다.

## 8. 최신 경제환경 해석 — 지표부터 (2026-08-28 소유주 지시)

소유주 지시: 「최신 데이터 가지고 **해석도 최신 경제환경을 고려하여** 제공하는 거를 말하는
거야. 다른 전문기사들처럼.」

### 진단 — 우리 데이터 안에서만 해석하고 있었다

`base-rate-300`(기준금리 3.00% 속보)을 다시 읽어 보면 우리 데이터 안에서는 잘한다.
정책 50bp 대 시장 151bp · 예금은 이미 3%대 · 환율은 인상 전에 이미 움직였다(그래서 인과를
세우지 않는다). 그런데 **그 기사가 인용한 「수요 측 물가 압력」을 우리 데이터로는 확인할 수
없었다.** 금리 기사를 **물가 없이** 쓰고 있었다는 뜻이다.

수집 계열 11개는 금리 3종·환율 2종·주가·원자재·무역이었고, **경제환경을 말할 축이 없었다.**

| 없던 지표 | 없으면 못 하는 말 |
|---|---|
| 한국 소비자물가 | 「지금이 인플레 국면의 어디인가」 |
| 미 연준 정책금리 | 「한미 정책금리 차가 얼마인가」(국고채-미국채만 있었다) |
| 미국 소비자물가 | 「글로벌 긴축 국면의 위치」 |
| 미국 실업률 | 「연준이 다음에 무엇을 볼까」 |

전문 매체와 갈리는 지점이 여기다. 「한은이 올렸다」에 그치지 않고 「물가가 X 로 여전히 목표
위이고, 연준이 Y 에 있어 정책금리 차가 Z 이므로…」를 붙이는 것이 해석이다.

### 1단계 — 지표 추가 (완료)

`data/sources.json` 에 넷을 넣었다: `cpi_kr`(ECOS) · `fedfunds`(FRED DFEDTARU) ·
`cpi_us`(FRED CPIAUCSL, `units=pc1`) · `unrate_us`(FRED UNRATE).
`collect.mjs` 의 FRED 호출에 **`units` 옵션**을 붙였다 — 물가는 지수보다 상승률로 읽히고,
우리가 계산하면 기준월이 어긋날 위험이 있으므로 **원 제공자의 계산을 그대로 쓴다.**

**★ API 코드를 로컬에서 검증할 수 없다.** ECOS·FRED 키는 vault(Drive 마스터키 필요)와 CI
Secrets 에만 있다. 특히 `cpi_kr` 의 `901Y009/0` 은 **미검증**이다.

### `npm run series-check` — 조용히 비는 것을 막는다 (신설)

`collect.mjs` 는 계열 하나가 실패해도 나머지를 지키려고 **「실패, 기존 값 유지」 한 줄만
남기고 넘어간다.** 그 로그는 CI 안에 묻히므로 **코드가 틀린 계열은 조용히 빈 채로 남는다.**
실제로 `gold` 는 8/25 에 소스를 교체한 뒤 **파일조차 없는 상태**였고 아무도 몰랐다.

점검기는 「정의는 있는데 파일이 없거나 비어 있는 계열」을 종료코드 1 로 알린다.
월별은 공표 지연이 커서 70일까지, 일별은 10일까지 정상으로 본다.
**아침 점검에 한 줄 돌릴 것.**

**★ `gold` 는 정의를 제거했다(2026-08-28).** FRED 가 **2022년에 IBA(LBMA 금가격) 데이터를
통째로 삭제**해서 `PGOLDUSDM` 은 404 이고 `GOLDAMGBD228NLBM` 은 그 공지 페이지로 리다이렉트된다.
**되살릴 수 없는 정의를 남기면 점검기가 영구히 빨간불이 되고, 상시 빨간불은 아무도 안 본다.**
금값이 다시 필요하면 FRED 밖의 출처를 찾아야 한다(미결로 남김).

**FRED 시리즈 ID 는 키 없이도 확인된다** — `https://fred.stlouisfed.org/series/<ID>` 를 열어
200 이면 존재한다. 이 방법으로 `DFEDTARU`·`CPIAUCSL`·`UNRATE` 는 확인했고 `PGOLDUSDM` 이
404 인 것도 이렇게 잡았다. **ECOS 는 이 방법이 없어 실제 호출로만 확인된다.**

**2026-08-28 실제 실행으로 검증 완료** — `workflow_dispatch` 로 파이프라인을 직접 돌려
**14개 전부 정상**을 확인했다. 미검증이던 `cpi_kr` 의 ECOS `901Y009/0` 도 맞았다.
**로컬에 키가 없어도 확인할 방법이 있다** — CI 를 수동 실행하고 커밋백을 받아 점검기를 돌리면 된다.

### ★ 검증에서 잡은 결함 — 지수와 상승률을 나란히 놓을 뻔했다

값을 실제로 보고서야 알았다. **미국은 상승률(%)이 오는데 한국은 지수가 온다.**

| | 오는 형태 | 최신 값 |
|---|---|---|
| `cpi_us` (FRED `units=pc1`) | **상승률 %** | 3.30% (2026-07) |
| `cpi_kr` (ECOS 901Y009) | **지수** (2020=100) | 119.77 (2026-07) |

이름만 「한국 소비자물가 상승률」로 붙여 뒀으니, 그대로 두면 **119.77 과 3.30% 를 나란히
놓는 사고**가 났다. 지수는 지수로 정직하게 이름 붙이고(`한국 소비자물가지수`, `pt`),
상승률은 `collect.mjs` 가 **파생 계열 `cpi_kr_yoy`** 로 계산한다(같은 달 전년 값과 나눈다).
검증: 2.16~3.16% 범위로 합리적이다.

**파생 계열은 `sources.json` 에 없으므로 `series-check` 의 `DERIVED` 배열에 따로 등재했다.**
여기 적지 않으면 파생이 조용히 사라져도 점검기가 「통과」라고 말한다.

### 이제 말할 수 있게 된 것 (2026-08-29 기준)

| 좌표 | 값 | 전에는 |
|---|---|---|
| 한미 **정책**금리차 | 3.00% − 3.75% = **−0.75%p** | **계산 자체가 불가** |
| 한국 실질 정책금리 | 3.00% − 2.79% = **+0.21%p** | 물가가 없어 불가 |
| 미국 실질 정책금리 | 3.75% − 3.30% = **+0.45%p** | 불가 |
| 미국 실업률 | 4.1% (하락 추세) | 불가 |

**「한은이 올렸다」에서 「물가 2.79% 위에서 실질금리가 겨우 +0.21%p 이고, 연준은 3.75% 로
0.75%p 위에 있다」로 갈 수 있게 됐다.** 이것이 전문 매체와 갈리던 자리다.
새 넷은 다음 성공 실행에서 채워진다 — 그때 이 점검기가 코드가 맞았는지 알려 준다.

### 남은 단계

2. **「현재 국면」을 기사 구조에 넣는다.** 지금 「다음에 확인할 것」은 체크리스트인데,
   그 앞에 **지금 국면이 어디인가**를 쓰는 자리가 필요하다. 좌표는 시계열이 주고
   **해석은 사람이 쓴다** — 자동 생성 문장은 절대규칙 4(AI스럽지 않게)에 걸린다.
3. **게이트가 요구한다.** 시점 의존 분야(money·trade·tariff)의 신규 기사에 그 요소를 필수로.

**1단계 없이 2·3 은 쓸 재료가 없다.** 지표가 채워진 것을 확인한 뒤 2단계로 간다.
