# 기사 대표 이미지 — 데이터 시각화로 (2026-08-28 소유주 결정)

**정본은 이 문서다.** 그전 방식(토리 카툰 히어로)은 아래 「왜 바꿨나」에 남긴다.

## 결정

소유주 지적: 「우리가 사용하는 기사 이미지가 너무 유치한거 같아.
전문가처럼 보이는 적합한 이미지로 기사를 써야겠어.」

- **앞으로 쓰는 기사의 대표 이미지는 그 기사의 핵심 수치를 세운 차트다.**
- **기존 116편은 그대로 둔다**(소유주 선택). 몇 편 돌려 보고 판단한 뒤 넓힌다.
- **토리는 사라지지 않는다** — 머리글·소개·`/story/`·그림함에 그대로 있다.
  기사 히어로 자리에서만 물러난다.

## 왜 바꿨나

실무자 키워드(HS코드·신용장·FOB/CIF)로 들어온 독자에게 카툰 히어로는
「데이터 리포트」로 읽히지 않는다. 영문판은 이미 같은 이유로
「데이터 기사는 무기명」으로 정해 뒀다(`english-edition.md` 5절).

차트 히어로가 우리에게 특히 맞는 이유는 따로 있다. **수치가 그대로 근거다.**
생성 AI 그림은 「예쁘지만 아무것도 주장하지 않는」 반면, 차트는 기사의
주장 그 자체다. 비용도 0이고, 데이터가 갱신되면 다시 구우면 된다.

## 만드는 법

```bash
# 0) 한글 폰트를 로컬로 (한 번만, 30초). 원격 폰트는 이 컨테이너에서 막힌다
node scripts/figures/fetch-fonts.mjs /tmp/hero-fonts

# 1) spec 을 쓴다 (아래 예시)
# 2) HTML 로 조판
node scripts/figures/hero-chart.mjs --spec spec.json --html /tmp/hero/index.html
#    fonts/ 를 같은 디렉토리에 두고 서빙한다
cp -r /tmp/hero-fonts /tmp/hero/fonts
python3 -m http.server 8150 --directory /tmp/hero &

# 3) 실제 브라우저로 구운다 (겹침·두부 검사 포함)
node scripts/figures/render-hero.mjs http://localhost:8150/ src/assets/hero/<슬러그>.jpg
```

## 조판 규칙 (dataviz 기준 + 우리 규약)

- **히어로 수치는 산세리프·비례숫자.** 세리프로 쓰면 장식으로 읽힌다.
  제목만 Hahmlet(세리프)이다. `tabular-nums` 는 표에서만 — 큰 숫자에 쓰면 헐렁해 보인다.
- **계열 하나에는 범례를 두지 않는다.** 제목이 계열을 말한다.
- **직접 라벨은 골라서만.** 모든 점에 숫자를 붙이지 않는다(보통 첫 점·마지막 점).
- **격자·축은 물러나 있게**(`--hair2`), 선은 3px.
- **글자는 잉크 토큰으로.** 계열 색을 글자에 쓰지 않는다.
- **색 규약**: 한글은 상승=빨강·하락=파랑, **영문(`lang:"en"`)은 상승=초록·하락=빨강**.
  `tone` 으로 강제할 수 있고, 없으면 시작·끝 값으로 자동 판정한다.
- **축은 절대 둘로 나누지 않는다**(dual-axis 금지). 척도가 다르면 차트를 나눈다.

## ★ 함정 둘 (둘 다 첫 판에서 실제로 터졌다)

1. **조판이 겹쳐도 그림은 «성공»으로 나온다.** 첫 판은 히어로 수치가 제목을 덮고
   x축 라벨이 출처와 겹쳤는데 스크립트는 아무 말도 안 했다.
   `render-hero.mjs` 가 **상자들의 교차를 실측해** 겹치면 종료코드 2 로 죽는다.
   나중에 3px 겹침도 이 검사가 잡았다.
2. **폰트가 안 물려도 «성공»으로 나온다.** 원격 폰트가 프록시에 막히면 글자가
   두부(□)로 구워진다. `render-hero.mjs` 가 `document.fonts` 로 확인하고 없으면 죽는다.
